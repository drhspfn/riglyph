# Riglyph v0.16.1 — Headless export and optional Rust native renderer

This release adds full browser-free animation export and an optional Rust CPU rasterizer, while preserving the TypeScript animation runtime, Universal IR, independent Spine Binary 4.1.23 importer and existing JS/WebGL2 backends.

## Headless rendering (A21)

- Render animations to independent transparent PNG frames without Chromium, DOM or WebGL.
- Use optional FFmpeg for H.264 MP4 (opaque background) or VP9 WebM with decoded alpha verification.
- Frame-index timestamps, clip loops, multi-track mixing, animation-aware stable camera, follow/fixed cameras, nearest/linear filtering, supersampling, progress, cancellation, streaming and transactional output.

## Native acceleration (A22)

- New optional `@riglyph/renderer-native` Node package; select `--backend native-cpu`, `js`, or `auto`.
- Prebuilt Windows x64, Linux x64 and macOS ARM64 CLI executables and shared C ABI libraries in the Assets section.
- Strict, versioned RGP1 binary protocol v1, C ABI v1, native binary v0.1.0, bounded framebuffer and texture cache, disjoint-band parallel rasterization.
- Preserves texture sampling, PMA, blending, dark tint, clipping-generated geometry and pixel-center conventions using canonical Riglyph DrawPackets.
- Supports full 4096×4096 atlas pages independently of the output framebuffer limits, correcting the native atlas upload failure.
- Python ctypes and compiled C consumers can provide draw packets and receive RGBA pixels. The native DLL/SO/DYLIB does **not** evaluate IR or Spine animations itself.

## Install and usage

```powershell
npm install @riglyph/cli@0.16.1
$env:RIGLYPH_NATIVE_BIN="C:\Riglyph\riglyph-native.exe"
riglyph render skeleton.ir.json --images ./textures --clip idle --backend native-cpu --native-threads 4 --fps 30 --width 800 --height 600 --out-dir ./frames
```

For native operation, download and extract the matching platform archive below. For browser-free JS rendering, use `--backend js` without a native binary. H.264/VP9 video requires FFmpeg and ffprobe.

## Validation and benchmarks

A22 Windows/Linux/macOS native CI, C/Python consumers, native/JS pixel parity, native PNG/MP4/VP9-alpha outputs and prior Riglyph browser/framework/workspace checks passed in the development branch. Release-tag checks should be green on the exact published commit.

A five-frame 800×600 synthetic-scene benchmark on a GitHub Linux CI runner measured PNG export 477 ms (JS) vs 124 ms (Rust), and H.264 692 ms (JS) vs 370 ms (Rust). These **are not** Ryzen 5 3600 results or a universal speedup claim. On the same small scene, the Rust four-thread median single-frame raster+IPC was slower than JS; performance varies by scene and hardware.

## Limitations

Native GPU rendering is not included; the Rust CPU backend is optional. TypeScript remains responsible for animation, constraints, camera and clipping generation. Only Spine Binary 4.1.23 is the target source profile; full parity for arbitrary third-party assets is not claimed. VP9 alpha depends on the decoder and H.264 cannot preserve source alpha. This is a pre-1.0 preview.
