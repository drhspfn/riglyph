# Riglyph v0.16.0 — Spine 4.1 Constraint Completion

Riglyph v0.16.0 expands support for the **Spine Binary 4.1.23** importer profile, completing the targeted Transform, IK, and Path Constraint functionality in the independent, version-neutral runtime.

## Highlights

- **Transform Constraints (A19):** World/Local × Absolute/Relative modes; rotation, translation, scale, and shear with independent mix channels, offsets, reflected and nonuniform transforms.
- **IK Constraints (A20):** one- and two-bone IK, bend directions, partial mixing, softness, compress/stretch, uniform scaling, degenerate configurations, and reflected/sheared parents.
- **Path Constraints (A20):** weighted/unweighted paths, animated deformation, constant/nonconstant speed, open/closed paths, position/spacing/rotation modes, reflected traversal, negative spacing, dynamic attachments and multi-bone constraints.
- **Numerical fixes:** preserve ordered Bézier sampling across repeated closed-path wraps and negative spacing; improve near-coincident chord handling.
- **Runtime integration:** preserve constrained world matrices across mixed Transform → IK → Path chains and repeated seeking.
- **Existing fixes included:** atlas 90°/270° UV correction, Windows package-tooling and safe CLI convert overwrite behavior.

## Verification

The final A20 PR passed **266/266 independent synthetic numerical IK/Path cases** (57 IK, 209 Path) and **439/439 tests per CI workspace environment** across Ubuntu/Windows with Node 22/24; browser and framework jobs also passed. These results describe the accepted A20 commit, **not** the new v0.16.0 release commit. Run fresh tag-specific CI before publishing.

The cubie scene was also reported working during local verification.

## Compatibility and scope

- Supported binary importer profile: **Spine Binary 4.1.23**.
- Numerical reference: compiled Spine Skeleton Viewer **4.1.24**, using independent synthetic observations.
- Universal IR, runtime and renderers remain Riglyph implementations.
- No claim of compatibility with every Spine export, full official source parity, or pixel-perfect third-party visual parity.

This is a pre-1.0 preview; APIs may evolve.
